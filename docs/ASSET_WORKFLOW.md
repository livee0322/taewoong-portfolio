# Asset workflow

## Principle

The portfolio shows evidence, not a generic mood board. Every published image must be a final or presentation-ready asset that can support the surrounding claim.

## Source to site

1. Start from the original source folder and its classification record.
2. Check filename, dimensions, category, visual quality, relevance, and privacy before selecting.
3. Keep only the approved final assets in the repository under `public/images/<project-or-section>/` using descriptive English filenames.
4. Use `next/image` through the shared media component, meaningful Korean alt text, and an editorial ratio appropriate to the material.
5. Before merge, verify the file is an image, it renders at desktop and mobile widths, and it does not expose private information.

## Exclusions and cautions

- Do not publish clip-art source files as if they were final work.
- Do not publish KakaoTalk captures or any asset containing personal information unless explicit approval and redaction are recorded.
- Do not use raw product-model imagery as a portfolio result unless it is part of the final designed output and supports the case story.
- Treat large detail pages as content to inspect: use a readable crop or a substantial vertical preview instead of a tiny card.

## Maintenance rule

Prefer a smaller, coherent selection of real work over a complete archive. When a project lacks final material, represent it in the career narrative rather than inventing a visual case study.
